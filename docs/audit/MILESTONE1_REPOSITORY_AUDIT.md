### Evidence limits — important

2. No API credentials exist in this sandbox. No real research provider, TTS provider or YouTube

3. Raw Actions logs and artifacts were unavailable: their download URLs redirect to

4. All 31 secret names and 11 variable names referenced by workflows were inventoried by name.
   Whether each is actually set in the repository could not be confirmed (the earlier audit also
   recorded HTTP 403 for secret listing). Their names are protected; no values were inspected.
5. A green CI result was not treated as proof that a production video was produced or uploaded.
   Step conclusions and release evidence were checked separately.

## 4. Existing content-generation paths

### 4.1 Documentary

1. `make_longform.yml` — weekly schedule, manual dispatch, or same-repository PR carrying
   `.github/documentary-production-request.json` with `[documentary-run]`.
2. `scripts/resolve_documentary_request.py` resolves topic, language, length and presenter mode.
3. `run.py` / `core/pipeline.py`, `core/editor_longform.py`, `core/voice.py`,
   `core/footage_engine.py`, `core/visual_production.py`, `core/documentary_storyboard.py`
   research, write, narrate, source footage and render.
4. `scripts/package_build_for_review.py --mode longform` builds the human-review package;
   `scripts/annotate_build_evidence.py` records measured evidence.
5. Release paths:
   - `release_documentary_auto.yml` (`workflow_run` after a successful dispatch/schedule build)
     → `scripts/upload_documentary_artifact.py --machine-only`;
   - `release_documentary_private.yml` (manual, six-field/signed review contract)
     → `scripts/release_review_package.py`;
   - the currently broken inline release job inside `make_longform.yml` (see PR #256).
6. `core/uploader.py::upload` sends `privacyStatus: private`, disables scheduling, verifies the
   channel, uses a source-run marker for idempotency, then reads status back with
   `get_video_status`.

### 4.2 Daily news Shorts

- **Automatic:** `daily-news-auto-short.yml` → `scripts/build_with_recovery.py` →
  `scripts/run_daily_news_short.py --upload` → `core/news_auto.py` →
  `core/news_source_verification.py`, `core/news_private_release.py::publish_news_job` →
  `core/uploader.py`. This path hard-codes private, verifies the channel and privacy read-back,
  and reuses an existing upload by marker.
- **Human-reviewed:** `daily-news-shorts.yml` (research queue) → GitHub issue approval →
  `news-story-review.yml`, `news-script-draft.yml`, `news-visual-asset-review.yml`,
  `daily-news-short-asset-prep.yml`, `daily-news-short-artifact-render.yml` /
  `daily-news-short-render.yml` → `release_shorts_private.yml` with `mode: daily_news`.
- Sources are RSS/public metadata plus claimed evidence packets; the existing docs explicitly
  say this is not full article-level fact verification.

### 4.3 Generic educational Shorts

- `make_shorts.yml` → `run.py shorts` / `core/pipeline.py` / `core/editor_shorts.py` →
  `scripts/package_build_for_review.py --mode shortform`.
- Scheduled and opted-in dispatched builds enter the inline strict QA/release job:
  `run_daily.py --format shorts --upload-latest --auto-private-release` →
  `core/release_gate.py`, `core/publish.py`, `core/uploader.py`.
- Manual release: `release_shorts_private.yml` with `mode: shortform` after human review.

### 4.4 Shared release invariants found in code

`core/uploader.py`, `core/publish.py`, `core/release_gate.py`, `core/news_private_release.py`,
`scripts/upload_documentary_artifact.py` and `scripts/release_review_package.py` already implement
private-only upload, channel verification, marker-based idempotency and privacy read-back. These
are valuable assets: the new studio must reuse or wrap them, not replace them with an unproven
uploader.

## 7. Production blockers and verified gaps

Severity reflects impact on the acceptance tests in the brief. “Recheck” means the issue is
documented in the repository but may have been fixed at the baseline commit.

### P0 — blocks claimed end-to-end success

1. **Documentary private release is not proven.** The inline release path fails before upload
   (`44390437941`), and all recorded `release_documentary_auto.yml` runs were skipped. PR #256
   is conflicting and not merged. A successful build is not an upload.
2. **Scheduled Shorts release failed at FFmpeg installation** (`44520142320`). The build existed,
   but the strict QA/upload job never ran. This is the exact package-repository/network class of
   failure in the brief. `validate.yml` has a retry pattern that can be reused in a new isolated
   helper, but the protected workflow itself must not be changed without owner approval.
3. **Daily news scheduled runs failed 5 of 9 times.** The failing step is the combined
   select/write/render/release step. The latest three runs succeeded, but without artifact access
   no verified YouTube ID or privacy read-back could be demonstrated here.
4. **No real upload evidence is available in this environment.** No OAuth credentials, no
   artifact download and no log access. Every upload claim must remain “not verified” until an
   owner-run, private, read-back-verified release is produced.

### P1 — quality and reliability risks

5. **News release reporting can be wrong.** PR #255 (mergeable) documents that the review package
   prints “Nothing was uploaded” after a verified private upload. Do not use package text alone
   as an upload signal; use `automatic_private_release.json` / `youtube-upload-result.json`.
6. **Documentary runtime is far above target.** The existing gap analysis records 116%, 118% and
   127% of requested runtime for the last production tests, with builds taking roughly 1.5–2.7
   hours. This threatens the free Actions budget and the “expected duration” QA criterion.
7. **Narration reliability.** Earlier builds had Edge male voices fail and fall back to robotic
   espeak narration, correctly failing audio QA. The head commit merged
   `feat/human-natural-fast-narration`; that change must be re-tested against real narration, not
   assumed fixed.
8. **Footage providers are unreliable.** Live checks recorded DVIDS 0/5, Coverr 4/5 with one
   HTTP 403, Library of Congress 429 in four of five runs, and Europeana 351 searches yielding
   2 results. Pixabay, NASA, Wikimedia and Internet Archive supplied most clips. Free fallbacks
   must stay free; a paid provider must never become mandatory.
9. **Relevance and rights remain human-reviewed.** Existing docs explicitly state that metadata
   word matching does not prove a clip depicts the claimed event, that Internet Archive once
   selected an unrelated upload, and that licence flags are attestations, not legal proof.

### P2 — engineering debt and governance

10. **Open PR conflicts.** #258, #256 and #251 conflict; #251 is explicitly WIP. Conflicts must
    be resolved deliberately; no force-push or bulk merge.
11. **`db/studio.sqlite` is tracked** while `.gitignore` excludes runtime databases. CI guards
    against modification. Its disposition (frozen record vs exported to the state branch and
    untracked) needs an owner decision.
12. **Zero-cost policy documentation is inconsistent.** `env.example` still mentions an optional
    ElevenLabs key and `CHANNEL_NAME=Power Codex`; `requirements.txt` includes optional
    `chatterbox-tts`; `news-short-one-click.yml` passes `REPLICATE_API_TOKEN` into a step that
    sets `FREE_ONLY_MODE=1`. No paid service is mandatory in the protected workflows, but these
    should be cleaned up in a reviewed, isolated change.
13. **Monolithic functions.** The earlier audit recorded six functions over 150 lines, including
    a 588-line `build_longform`. New v2 components should be small from the start.
14. **Actions are pinned by tag rather than commit.** Low risk relative to the blockers, but
    worth addressing in a separate supply-chain pass.
15. **Hindi subtitles / channel language defaults.** Existing workflows expose Hindi and
    Hinglish inputs, but the master brief requires English narration/subtitles for the new
    English production path. The v2 configuration must default to English without changing
    existing workflow inputs.
16. **No `production_v2` implementation exists yet.** There is no new research dossier format,
    claim-to-source graph, scene contract, quality decision JSON or topic/story-history layer
    matching the requested seven-field report. These are Milestones 3–8, not Milestone 1.

### Rules that will not change

- No protected workflow YAML edits without explicit owner approval and a rollback plan.
- No schedule or cron additions/duplications; no increased frequency without a measured budget.
- No secret/variable renames, token logging, privacy changes, or channel changes.
- No upload without passing critical QA, private status, channel match and read-back verification.
- No claim that a build/artifact/render equals a successful YouTube upload.
- No mandatory paid provider; if a free provider fails, report the limitation or use another
  genuinely free source.
